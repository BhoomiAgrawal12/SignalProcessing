rf::analyzer
automated blind analysis of .IQ / .WAV recordings
github

from raw RF samples
to decoded payload, blind.

rf-analyzer takes an unknown IQ or WAV recording and works its way to an analyst-readable interpretation: CFAR detection, parameter estimation, two-engine modulation classification, soft-bit demodulation, and a GF(2) bit-layer engine that blindly identifies scramblers, interleavers, FEC (convolutional, Reed-Solomon, LDPC), frames, CRCs - then a payload-intelligence stage that says what the recovered bytes mean, with evidence, confidence and limitations.

S0-S2 · front end

WAV/RIFF with the SDR auxi chunk, automatic raw-IQ format sniffing, conditioning, CFAR detection on the waterfall. A headerless file's sample rate is reported unknown, never invented.

S3-S5 · measurement

ITU occupied bandwidth, M2M4 SNR, cyclostationary symbol rate, FSK tone histograms, and cumulants + CVNet-RF fused with disagreement surfaced, never averaged away.

S6-S7 · demodulation

Feedforward timing recovery, decision-directed carrier tracking, soft LLRs, and a full phase/IQ/polarity ambiguity fan-out - blind analysis is a search, not a pipeline.

S8-S10 · bit layer

Bit-packed GF(2) rank deficiency finds interleaver and codeword periods through scrambling; dual-code tests identify convolutional codes, syndrome sweeps identify RS and LDPC; frame periods, sync words and CRCs are hunted and validated.

S11 · payload intelligence

What do the recovered bytes mean? Forensics, text and encoding discovery, structure and field inference across frames, compression detection with real decompression, conservative encryption assessment, validated protocol fingerprints.

S12 · reporting

JSON, CSV, payload, SigMF annotations, PDF sheet, GNU Radio flowgraph. Every number carries its confidence and the method that produced it; unknown is a valid answer.

the pipeline

recording (.iq / .wav / .sigmf)
  S0 ingest -> S1 condition -> S2 detect -> S3 channelise -> S4 estimate
  -> S5 classify -> S6 demodulate -> S7 ambiguity + descramble
  -> S8 de-interleave -> S9 FEC identify + decode -> S10 frames + CRC
  -> S11 payload intelligence -> S12 report and export

The browser runs S0-S5 on uploaded recordings; the desktop engine (same repository, one pip install) runs the full chain and its reports render in the viewer with an animated stage-by-stage flow of exactly what was executed, skipped and found.
